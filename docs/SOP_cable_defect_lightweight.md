## 1. 목적 및 성공 기준

### 1.1 목적
소형 하드웨어(엣지 디바이스)에서 실시간 동작 가능한 케이블 단면 불량(OK/NG) 판정 모델을 확보한다. 성능 비교 기준선(baseline)으로 YOLO 계열 검출 모델을 사용한다.

### 1.2 연구 질문
1. 불량 판정 문제를 (a) 지도학습 검출, (b) 지도학습 분류, (c) 비지도 이상탐지 중 어떤 태스크로 푸는 것이 정확도-연산량 균형에서 유리한가?
2. 입력 해상도, 백본 폭, 양자화 중 어떤 축의 경량화가 미검율 손실 대비 가장 효율적인가?
3. 목표 하드웨어에서 지연시간 예산을 만족하면서 미검율을 관리 가능한 수준으로 유지할 수 있는가?

### 1.3 성공 기준 (Definition of Done)
아래 항목을 **모두** 충족해야 연구 완료로 판정한다.

| 항목 | 기준 | 측정 방법 |
|---|---|---|
| 미검율 (NG를 OK로 오판) | 고정 과검율 5% 조건에서 ≤ 5% | 홀드아웃 테스트셋, §7.2 |
| 이미지 레벨 AUROC | ≥ 0.95 | 홀드아웃 테스트셋 |
| 모델 크기 | ≤ 10 MB (INT8 기준) | 배포 파일 바이트 수 |
| 추론 지연시간 | 목표 하드웨어에서 ≤ 100 ms/frame (단일 스레드) | §9 벤치마크 프로토콜. **개발 CPU 무경합 실측(2026-09-22): 확정 구성 18.75 ms (p95 21.68)** — 약 5배 여유. 타깃 하드웨어 재측정 필요 |
| 피크 메모리 | ≤ 256 MB RSS | §9 벤치마크 프로토콜 |
| 재현성 | 동일 시드·설정으로 지표 재현 오차 ≤ ±1%p | §11 |

> 위 수치는 초기 목표값이다. §2 킥오프에서 실제 타깃 하드웨어와 라인 택트타임이 확정되면 1회에 한해 개정하고, 개정 이력을 §13에 남긴다.

**해석 — 모델 설계에 미치는 영향**
- bbox 변 길이 중앙값이 이미지 변의 **17~48%**로, COCO 기준 "대형 객체"에 해당한다. 극소 객체 검출 문제가 아니므로 **입력 해상도를 공격적으로 낮출 여지가 크다**. 1024 → 640 → 384 → 256 스윕이 타당하다.

- `missing_wire`는 bbox가 가장 작고(폭·높이 중앙값 17%) 면적 중앙값도 1.80%로 최소 수준이다. 해상도 축소에 가장 민감할 클래스로 우선 감시한다.
- `cable_swap`, `missing_cable`, `missing_wire`는 국소 텍스처 이상이 아니라 **구성/배치의 논리적 오류**다. 패치 단위 이상탐지 기법(PatchCore, PaDiM)이 구조적으로 불리한 클래스이며, 전역 문맥을 보는 분류/검출 모델이 유리할 가능성이 있다. 이 가설은 §7.3 클래스별 분해에서 검증한다.
- `cable_swap`은 면적 분포가 4.95~6.47%로 매우 좁다(분산 최소). 케이블 위치가 고정된 촬영 조건이므로, 모델이 결함 자체가 아니라 **촬영 정렬 패턴을 암기**할 위험이 있다. §4.4 증강 규칙(색상 변형 금지)과 함께 주의한다.

## 4. 데이터 준비 절차

### 4.1 무결성 검증 (SOP-DATA-01)

**목적**: 학습 전 데이터 결손·손상·규격 불일치를 차단한다.
**입력**: `mvtec/cable/`
**산출물**: `reports/data_integrity_cable.csv`, `reports/data_integrity_cable.md`

**절차**
1. 모든 PNG를 열어 손상 여부, 해상도(1024×1024), 채널 수(RGB=3, mask=1)를 확인한다.
2. `test/<class>/NNN.png` ↔ `ground_truth/<class>/NNN_mask.png` 인덱스 대응을 양방향 검사한다.
3. 마스크 픽셀값이 {0, 255} 이진인지 확인한다. 중간값이 있으면 임계 127로 이진화하고 로그에 남긴다.
4. `test/good`에 대응 마스크가 없음을 확인한다(정상 — 빈 마스크로 취급).
5. 클래스별 보유 수량을 공식 수량과 대조하여 결손표를 출력한다.

**합격 기준**: 손상 파일 0건, 규격 불일치 0건, 결손 0건 (§3.1 공식 수량과 완전 일치). 2026-09-21 기준 통과 상태이며, 데이터 디렉토리를 변경할 때마다 재실행한다.

### 4.2 라벨 변환: mask → bbox / 분류 라벨 (SOP-DATA-02)

**목적**: YOLO 학습에 필요한 bbox 라벨과 분류 라벨을 마스크에서 생성한다.
**입력**: `ground_truth/<class>/*_mask.png`
**산출물**: `data/yolo/labels/**/*.txt`, `data/labels_index.csv`

**절차**
1. 마스크를 이진화 후 **연결요소(connected components)** 분석한다 (8-연결).
2. 면적이 전체의 0.02% (≈210 px) 미만인 요소는 노이즈로 간주해 제거한다. 임계값은 설정 파일에 노출하고 제거된 요소 수를 로그에 남긴다.
3. 각 연결요소의 외접 사각형을 bbox로 변환하고, YOLO 정규화 포맷으로 기록한다.
   ```
   <class_id> <cx/W> <cy/H> <w/W> <h/H>     # 모두 0~1 정규화, 공백 구분
   ```
4. 클래스 ID 매핑을 `data/classes.yaml`에 **고정**한다. 이후 변경 금지(변경 시 모든 라벨 재생성 + 실험 재실행).
5. `test/good` 이미지는 **빈 라벨 파일**(0바이트 `.txt`)을 생성한다. 파일 자체를 누락시키면 Ultralytics가 해당 이미지를 배경 샘플로 취급하지 않고 경고를 낸다.
6. 이진 분류 라벨은 디렉토리명으로 파생한다: `good` → 0(OK), 그 외 → 1(NG).

**검증 (필수)**: 무작위 20장에 대해 원본 이미지 위에 생성된 bbox를 오버레이한 PNG를 `reports/label_check/`에 저장하고 **육안 확인**한다. 이 단계를 건너뛰면 좌표 순서 오류(xy 뒤바뀜)를 학습 종료 후에야 발견하게 된다.

**주의 — 다중 인스턴스**: `combined` 클래스는 정의상 복수 결함이 한 이미지에 존재한다. 연결요소가 여러 개 나오는 것이 정상이며, bbox 개수를 1개로 강제 병합하지 않는다.

### 4.3 데이터 분할 설계 (SOP-DATA-03)

**목적**: 누수 없는 재현 가능한 분할을 확정한다.
**산출물**: `data/splits/fold{0..4}.json`, `data/splits/holdout.json`

**핵심 제약**: MVTec AD 원본 분할은 train에 정상만 있고 불량은 전부 test에 있다. 지도학습(YOLO)은 이 분할을 그대로 쓸 수 없다. 반면 비지도 이상탐지는 원본 분할을 그대로 써야 문헌값과 비교가 가능하다. **따라서 두 개의 분할 체계를 병행 정의한다.**

**분할 A — 비지도 이상탐지용 (원본 유지)**
- train: `train/good` 전체
- test: `test/` 전체 (good + 불량)
- 문헌 비교가 가능한 유일한 설정이므로 **변경 금지**.

**분할 B — 지도학습(YOLO/분류)용 (재분할)**
- 불량 이미지 전체를 **클래스 층화(stratified) 5-fold 교차검증**으로 분할한다.
- 정상 이미지는 `train/good` 224 + `test/good` 58 = 282장을 풀로 삼아, 각 fold의 train/val에 불량:정상 비율이 일정하도록 배분한다.
- 불량 표본이 92장으로 여전히 적으므로 **단일 분할의 점추정치는 신뢰할 수 없다. 5-fold 평균 ± 표준편차로만 보고한다.** fold당 불량 검증 표본이 약 18장이므로, recall 1건 차이가 약 5.5%p로 나타난다는 점을 해석 시 감안한다.
- 추가로 fold와 독립적인 **홀드아웃 세트**를 클래스당 최소 2장씩 떼어 보관한다. 홀드아웃은 §1.3 최종 합격 판정에만 1회 사용하고, 모델 선택·튜닝에 절대 사용하지 않는다.

**누수 방지 규칙**
- 분할은 **이미지 파일 단위**로 수행하며, 한 이미지에서 파생된 크롭·증강본은 반드시 같은 분할에 속한다.
- 분할 결과는 JSON으로 고정 저장하고, 코드에서 매번 난수로 재분할하지 않는다.
- 분할 생성 시 `seed=42`를 사용하고 시드를 JSON에 함께 기록한다.

### 4.4 전처리 및 증강 (SOP-DATA-04)

**전처리 (학습·추론 공통, 불일치 금지)**
- 리사이즈: letterbox (종횡비 유지, 패딩). 원본이 정사각이므로 실질적으로 단순 리사이즈.
- 정규화: ImageNet 통계 또는 단순 `/255`. **선택한 방식을 설정 파일에 고정하고 배포 전처리와 동일하게 유지한다.** 이 불일치가 배포 단계 정확도 급락의 가장 흔한 원인이다.

**증강 (학습 시에만)**

> **확정 (2026-09-22, Stage 1 결과)**: 기본 증강을 `robust`로 한다. Stage 0에서 색·반사 축이 무너진 것이 확인됐고, Stage 1에서 이 증강이 해당 축의 강건성을 크게 올리면서 추론 비용은 0이기 때문이다.

| 항목 | `medium` (기존) | **`robust` (확정)** |
|---|---|---|
| 플립 / 90° 회전 | 사용 | 사용 |
| 연속 회전 | 없음 | **±40°** |
| 평행이동 | ±5% | **±10%** |
| 스케일 | ±10% | **±20%** |
| 밝기·대비 | ±20% | **±30%** |
| 채널 게인 (색바램 모사) | 없음 | **±15%, 휘도 보존** |
| 정반사 하이라이트 합성 | 없음 | **면적 ≤3%, 확률 0.5** |
| 약한 가우시안 노이즈 | 사용 | 사용 |

- **금지**: 강한 색상 변형(Hue shift). 케이블 절연체 색상이 `cable_swap` 판별의 직접 근거이므로 색상을 흔들면 라벨이 거짓이 된다. 위 **채널 게인은 Hue 회전이 아니라 휘도를 보존하는 선형 게인**이며 조명 색온도·절연체 퇴색을 모사한다 — 색 순서를 바꾸지 않으므로 이 금지 항목에 해당하지 않는다.
- **증강 범위는 §8.2 강건성 시험 섭동보다 좁게 유지한다**(채널 게인 ±15% vs 시험 30%, 정반사 ≤3% vs 시험 10%). 증강과 시험 분포가 같아지면 강건성 측정이 의미를 잃는다.

**전처리 (Stage 1 확정, 2026-09-22)**

학습·추론에 동일하게 `gray+spec`을 적용한다. 구현은 `src/data/preprocess.py`.

| 요소 | 내용 | 근거 |
|---|---|---|
| `gray` | 그레이월드 정규화 — 채널별 평균으로 나눠 색 캐스트 제거 | 색바램·황변이 채널 게인으로 모형화되며 이것이 **정확한 역연산**이다. 채널 캐스트 15.5% → 4.1% |
| `spec` | 정반사 억제 — 포화 화소 중 **국소 표준편차가 낮은** 넓은 덩어리만 제거, 마스크 인식 저해상도 블러로 채움 | 포화 화소 6.28%는 대부분 구리 소선 고유 반사다. 단순 임계·면적 필터는 이를 파괴했고(무섭동 25.8dB·21.2dB 훼손), 국소 분산이 유효한 판별자였다(외란 0.36 vs 구리 6.12) |

> **채택하지 않은 요소**: `disk`(원판 정규화) · `rot`(회전 정렬). Stage 0에서 기하 축이 실측 변동의 10배까지 강건함이 확인돼(회전 ±80°에서 AUROC 0.997) 추가 비용만 발생한다. 구현은 남겨 두되 기본 비활성이다.
>
> **색도 정규화(`chrom`)도 미채택** — 출력 색도가 입력 색도와 항등이라 채널 게인을 제거하지 못한다(수학적으로). 조도 변동에만 유효하며, 밝기 축은 이미 강건하다.
- **주의**: Mosaic/MixUp은 표본이 적을 때 도움이 되지만 결함의 문맥을 파괴할 수 있다. 사용 여부를 **ablation 항목으로 분리 측정**한다(§8.2).

## 7. 평가 프로토콜

### 7.1 지표 정의

**이미지 레벨 (판정 성능 — 주 지표)**
- AUROC, AUPRC
- **미검율 (Miss rate / escape rate)** = FN / (TP+FN) — 산업 현장 최우선 지표
- **과검율 (Over-kill rate)** = FP / (FP+TN)
- Recall @ FPR=5% — §1.3 합격 판정 지표
- F1, Balanced Accuracy

**픽셀/영역 레벨 (위치 성능 — Track A/B)**
- Pixel AUROC, PRO (Per-Region Overlap)
- mAP@0.5, mAP@0.5:0.95 (Track A)

> **주의 (P1 육안 검증에서 확인)**: `bent_wire`, `cut_outer_insulation`의 GT 마스크는 가늘고 휜 곡선 형태라 외접 bbox가 실제 결함 면적보다 훨씬 넓다. 이 클래스들에서 **mAP@IoU는 검출 품질을 과대평가한다.** Track A 평가 시 mAP 단독으로 결론내지 말고 픽셀 레벨 PRO를 반드시 병행한다.
>
> `combined`(id 2)는 결함 유형이 아니라 "복수 결함 존재"를 뜻하는 메타 라벨이다. 8클래스 검출에서 타 클래스와 혼동될 소지가 있으므로, 혼동행렬에서 `combined` 관련 오분류를 별도로 확인한다.

**하드웨어 지표 (필수 동시 보고)**
- 파라미터 수, GFLOPs
- 배포 파일 크기 (MB)
- 지연시간: p50 / p95 (ms), 워밍업 20회 후 200회 측정
- 피크 RSS (MB), 전력(측정 가능한 경우)

> **보고 규칙**: 정확도 지표와 하드웨어 지표는 **항상 같은 표에 함께** 기재한다. 정확도만 단독 보고하는 표는 본 연구에서 무효로 간주한다.

### 7.2 판정 임계값 결정 절차 (SOP-EVAL-01)
1. 검증셋(val fold)에서 이상 점수 분포를 산출한다.
2. §2.1에서 확정한 미검:과검 비용 비율로 기대비용을 최소화하는 임계값 τ를 탐색한다.
3. 비용 비율 미확정 시 기본 정책: **과검율 5% 고정 하에서 미검율 최소화**.
4. τ는 **검증셋에서만 결정**한다. 테스트셋/홀드아웃으로 τ를 조정하면 그 결과는 무효다.
5. 확정된 τ를 `runs/<EXP_ID>/metrics.json`에 기록하고, 배포 아티팩트에 동봉한다.

> **정책 보완 (2026-09-21, Track C 실측 근거)**: 두 분포가 완전분리되면 ROC가 돌려주는 임계값은 빈 구간의 한쪽 끝에 붙는다. 같은 혼동행렬을 유지하면서 양쪽 점수 군집의 중앙(로그 스케일 기하평균)으로 옮기는 **마진 tie-break**를 적용한다(`src/eval/metrics.py: choose_threshold`).
>
> **더 중요한 제약 — τ는 fold/환경 간 이식되지 않는다.** Track C 640px 실측에서 정상 점수 중앙값이 fold마다 2e-11 ~ 2e-4로 **8자릿수** 차이났고, 분리 구간 폭은 0.25~0.81 log10에 불과했다. 한 환경에서 정한 절대 확률 임계를 다른 환경에 그대로 쓰면 판정이 무너진다. 배포 시에는 다음 중 하나를 적용한다:
> (a) 현장 정상 표본으로 τ 재보정 (권장 — 설치 절차에 포함)
> (b) 절대 확률 대신 정상 표본 점수의 백분위수 기반 임계
> (c) 온도 스케일링 등 확률 보정 후 고정 임계
> 어느 방식이든 §9.2 배포 아티팩트에 보정 절차와 보정용 데이터 요건을 함께 동봉한다.

### 7.3 클래스별 분해 보고 (필수)
전체 평균 지표만으로는 §3.2에서 제기한 가설을 검증할 수 없다. **모든 실험에서 불량 클래스별 recall을 분해 보고한다.**

| 클래스 | n | Recall @ τ | 비고 |
|---|---|---|---|
| bent_wire | 13 | | |

### 7.4 통계적 신뢰성
- 5-fold 평균 ± 표준편차로 보고한다. **단일 fold 결과로 모델 우열을 주장하지 않는다.**
- 모델 A와 B의 비교는 동일 fold 분할·동일 시드에서 수행한다.
- 표본이 적으므로 차이가 표준편차 이내면 "유의한 차이 없음"으로 결론낸다. 소수점 셋째 자리 차이를 성능 개선으로 서술하지 않는다.

## 8. 학습 절차

### 8.1 기준선 확립 (SOP-TRAIN-01)
**순서를 지킨다. 경량화는 기준선 확보 후에만 착수한다.**

1. Track B (EfficientAD-S, 원본 분할) — 가장 적은 가정으로 동작하는 참조점 확보
2. Track A (YOLO11n, 640px, FP32, 5-fold) — 비교 기준선
3. Track C (MobileNetV3-Small, 640px, FP32, 5-fold) — 경량 본선 시작점

> **실행 순서 변경 (2026-09-21, §2.2 대안 (c) 채택)**: GPU 미확보 상태이므로 **Track C를 먼저 수행**한다. Track A(YOLO)는 CPU에서 5-fold 학습이 현실적이지 않아 GPU 확보 후로 미룬다. Track B도 GPU 확보 후 수행한다. 이 변경으로 Track A/B/C 상호 비교는 GPU 확보 시점까지 미완 상태로 남는다 — Track C 단독 결과로 태스크 선정(§1.2 연구질문 1)을 결론내지 않는다.

각 실험마다 `runs/<EXP_ID>/`에 설정·환경·가중치·지표를 남긴다(§11).

**학습 기본값 (Track A/C 공통, 이후 §8.2에서 조정)**
```yaml
seed: 42
epochs: 300            # early stopping patience=50
batch: 16              # GPU 메모리에 맞춰 조정, 변경 시 lr 동반 조정
optimizer: AdamW
lr0: 0.001
cos_lr: true
warmup_epochs: 3
weight_decay: 0.0005
pretrained: true       # COCO/ImageNet 사전학습 가중치 사용 (소량 데이터에서 필수)
```

**주의**: 데이터가 적으므로 사전학습 가중치 없이 처음부터 학습(scratch)하지 않는다. 또한 epoch 수가 많으므로 early stopping과 best-checkpoint 저장을 반드시 켠다.

> **Track C 실측 기반 조정 (2026-09-21)**: CPU 전용 환경에서 MobileNetV3-Small · 640px의 학습 속도는 **약 70초/epoch**(12스레드, `num_workers=0`)이다. 300epoch × 5fold = 약 29시간으로 비현실적이다. 타이밍 실험에서 ImageNet 사전학습 가중치 사용 시 **epoch 2에 이미 val AUROC 0.98**에 도달해 수렴이 매우 빠름을 확인했으므로, Track C 기준선은 **epochs 50 / patience 15**로 축소해 실행한다. GPU 확보 후 Track A를 수행할 때는 원래 값(300/50)을 사용한다. best-checkpoint는 val AUROC 기준으로 저장한다.
>
> `num_workers > 0`은 Windows의 프로세스 spawn 오버헤드와 memmap 재열기 비용 때문에 **오히려 2.6배 느렸다**(70s → 181s/epoch). `num_workers=0` 고정.

### 8.3 Stage 1 강건성 처방 판정 (2026-09-22)

Stage 0에서 무너진 3축(색바램·황변·정반사)에 대해 값싼 처방 3종을 비교했다.
**판정 기준은 결과를 보기 전에 등록했다** — `reports/stage1_decision_criteria.md`.

합격 조건(3축 **전부** 충족): 최대 섭동에서 AUROC ≥ 0.95 · 재보정 τ 미검율 ≤ 5% · 고정 τ 과검율 < 50%

| 변형 | 구성 | 무섭동 | 색바램 30% | 황변 30% | 정반사 면적10% |
|---|---|---|---|---|---|
| 기준선 | — / medium | 0.9992 | 0.8924 / 39.2% / 65.7% | 0.9018 / 37.4% / 81.5% | 0.8273 / 56.3% / 100.0% |
| A | — / robust | 0.9971 | 0.9835 / 10.6% / 13.8% | 0.9750 / 9.2% / 18.9% | 0.9210 / 26.2% / 57.9% |
| B | gray+spec / medium | 0.9988 | **0.9974 / 2.7% / 5.2%** | **0.9986 / 0.0% / 3.0%** | 0.8382 / 57.7% / 100.0% |
| **C** | gray+spec / robust | 0.9980 | **0.9974 / 1.3% / 2.2%** | **0.9977 / 1.3% / 2.6%** | 0.9228 / 35.6% / 57.1% |

(값 = AUROC / 재보정 미검율 / 고정 τ 과검율)

#### 판정 결과 — 사전 등록 기준으로는 **전원 불합격**

세 변형 모두 **정반사 축에서 탈락**했다. 규칙대로라면 "값싼 처방 불충분 → Stage 2 검토"로 귀결된다.

#### 그럼에도 C를 채택한 근거

사전 등록 기준은 3축을 **동등하게** 놓고 전부 충족을 요구했다. 실제 결과는 2축이 완전히 해결되고
1축만 남은 형태이므로, 기준을 사후에 완화하는 대신 **결정을 분리**한다.

1. **색 축은 해결됐다.** C 기준 색바램 0.8924→0.9974(미검 39.2%→1.3%), 황변 0.9018→0.9977(37.4%→1.3%).
   그레이월드가 채널 게인의 역연산이라는 예측이 실측으로 확인됐다.
2. **정반사는 증강이 전처리보다 낫다.** A 0.9210 > B 0.8382. 전처리가 PSNR을 +2.2 dB 복원했음에도
   모델 성능은 오르지 않았다 — **픽셀 복원과 표현 보존은 다른 문제**다.
3. **두 처방은 상보적이다.** C가 색 축 최고(미검 1.3%)이면서 정반사도 A와 동급(0.9228).
   합쳐서 나빠지는 축이 없다.
4. **비용이 작다.** 전처리 6.2 ms 고정(해상도 무관), 무섭동 AUROC 손실 0.0012.
5. **B는 기각.** 정반사 미개선(과검 100% 유지) + 색 축도 C보다 못하다.

#### 미해결로 분리한 과제

**정반사 대응**을 독립 과제로 승격한다(§13 리스크 등재). 값싼 처방으로 해결되지 않음이 확인됐으므로
Stage 2(DINOv2 증류 등) 검토의 **정당한 근거**가 생겼다. 다만 착수 전 다음을 먼저 확인한다:

- 실제 라인에서 정반사가 얼마나 발생하는가 — **조명 설계·편광 필터로 물리적 저감이 모델보다 저렴하다**
- 합성 정반사 모형이 현장 반사와 얼마나 닮았는가 (§8.2 섭동 모형의 타당성)

#### 기록해 둘 한계

- A·C의 robust 증강은 시험 섭동과 **같은 축**을 학습에서 겪었다(범위는 더 좁게). 그 개선은
  **분포 내 강건성**이며 미지 변동에 대한 일반화가 아니다.
- 모든 수치는 val fold 기준이고 τ도 같은 val에서 정해 낙관적으로 편향돼 있다. 홀드아웃 미사용.

## 9. 경량화 및 배포 검증

### 9.1 경량화 순서 (SOP-OPT-01)
비용 대비 효과 순으로 적용한다.

1. **입력 해상도 축소** — 연산량이 해상도의 제곱에 비례하므로 효과가 가장 크다. §3.2 기준 640px까지는 손실이 작을 것으로 예상되나 `poke_insulation` 등 소형 결함 recall을 반드시 확인한다.
   - **Track C 실측 (2026-09-21)**: 640 → 384 → 256 전 구간에서 미검율 0%, AUROC 0.999대 유지. 소형 결함 감시 3종(`poke_insulation`/`cut_outer_insulation`/`missing_wire`) recall도 전부 1.000. **256px가 DoD 충족 최경량**(0.16 GFLOPs, 640 대비 연산량 0.16×). 다만 표본이 작아 미세 차이는 유의하지 않다(§7.4). 256px 미만은 미검증이다.
   - **전처리가 지연시간 하한을 만든다**: 센서 리사이즈가 고정비로 남는다. 카메라에서 저해상도로 직접 취득할 수 있으면 추가 이득이 크다.
   - **무경합 실측 (2026-09-22, 단일 스레드)**: 256px 전처리 없음 12.59 ms / `gray+spec` 18.75 ms / 384px 27.07 ms / 640px 52.16 ms. Stage 1 전처리 비용은 **6.2 ms 고정**(해상도 무관)이다. 이전 측정치는 학습과 CPU 경합 상태여서 약 2배 부풀려져 있었다.
   - **멀티스레드가 오히려 느리다**: 256px 기준 단일 12.59 ms vs 10-스레드 17.17 ms. 모델이 작아 스레드 동기화 오버헤드가 병렬 이득을 넘는다. **엣지 배포는 단일 스레드가 유리**하다.
2. **백본 축소** — nano 스케일 또는 width multiplier 축소.
3. **PTQ INT8 양자화** — 대표 데이터셋(calibration set)으로 학습 데이터 100~200장을 사용한다. 캘리브레이션 데이터에 **불량 이미지를 포함**시킨다(정상만으로 캘리브레이션하면 불량 구간 활성값 범위를 놓친다).
4. **QAT** — PTQ에서 정확도 손실이 2%p를 초과할 때만 수행한다.
5. **구조적 가지치기(pruning)** — 위 단계로 목표 미달 시에만. 비구조적 가지치기는 대부분의 엣지 런타임에서 실속도 이득이 없으므로 **구조적 가지치기만** 사용한다.
6. **지식 증류(KD)** — 큰 교사 모델(YOLO11s 등) → 경량 학생. 표본이 적을 때 정규화 효과도 기대된다.

**각 단계 후 반드시 §7 전체 지표를 재측정**한다. 경량화 단계별 정확도 손실을 누적 기록하여 파레토 프론티어를 그린다.

### 9.2 Export (SOP-OPT-02)
타깃 하드웨어별 경로:

| 타깃 | 런타임 | export 경로 |
|---|---|---|
| Raspberry Pi 4/5 (CPU) | ONNX Runtime / TFLite | PyTorch → ONNX → (선택) TFLite INT8 |
| Jetson Orin Nano | TensorRT | PyTorch → ONNX → TensorRT engine (FP16/INT8) |

**Export 후 필수 검증 — 수치 동등성**
동일 입력 20장에 대해 PyTorch 출력과 export 모델 출력을 비교한다.
- FP32/FP16: 최대 절대오차 < 1e-3 (FP16은 < 1e-2)
- INT8: 수치 비교 대신 **판정 결과 일치율 100%**, 이상 점수 상관계수 > 0.99

이 검증을 통과하지 못한 아티팩트는 벤치마크로 진행하지 않는다.

## 11. 재현성 규약

**모든 실험은 다음을 남긴다. 누락된 실험은 결과로 인정하지 않는다.**

1. `config.yaml` — 사용된 전체 설정 스냅샷 (기본값 포함, 참조가 아닌 실값)
2. `env.txt` — `pip freeze`, Python 버전, OS, GPU/CPU 모델, 드라이버 버전
3. `git_rev.txt` — 커밋 해시. **uncommitted 변경이 있는 상태로 실험을 돌리지 않는다.**
4. 시드 고정: `random`, `numpy`, `torch`(+`torch.cuda`) 전부. `torch.use_deterministic_algorithms(True)` 사용 시 속도 저하를 감수하고 기록한다.
5. 분할 파일 경로와 해시
6. `metrics.json` — §7.1 전 지표 + 임계값 τ

**결과 갱신 규칙**: 코드나 데이터가 바뀌면 이전 실험 결과를 수정하지 않고, 새 `EXP_ID`로 재실행한다. 과거 결과는 보존한다.

## 부록 A. 데이터 라이선스
MVTec AD는 **CC BY-NC-SA 4.0** (비상업적 연구 목적)으로 배포된다. 상업적 제품에 본 데이터로 학습한 모델을 사용하려면 별도 라이선스 확인이 필요하다. 사내 실데이터로의 전이 계획을 별도 수립할 것.

## 부록 B. 참고 비교 기준 (MVTec AD `cable`, 문헌 보고값)
Track B 결과의 타당성 확인용 참조치. 구현·전처리 차이로 재현값은 달라질 수 있으므로 **절대 비교가 아닌 자릿수 확인 용도**로만 사용한다.

| 방법 | Image AUROC | Pixel AUROC |
|---|---|---|
| PaDiM | ~0.92 | ~0.96 |
| PatchCore | ~0.99 | ~0.98 |
| EfficientAD | ~0.98 | ~0.96 |

`cable`은 MVTec 15개 카테고리 중 난도가 높은 편에 속하며, 특히 구조적 결함 클래스에서 방법 간 편차가 크다.
