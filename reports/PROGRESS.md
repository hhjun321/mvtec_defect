## 1. 데이터 — 복원과 검증

초기 로컬 사본은 부분 다운로드본이었다. Drive 원본 zip에서 전량 복원했다.
원인은 Drive의 대용량 폴더 다운로드가 아카이브를 임의 분할하는데 일부 파트만 압축 해제한 것이었다.

| 항목 | 복원 전 | 복원 후 | 공식 |
|---|---|---|---|
| test 총계 | 91 | **150** | 150 |
| test 불량 클래스 | 3종 | **8종** | 8종 |
| 불량 이미지 | 33 | **92** | 92 |
| ground_truth 마스크 | 57 | **92** | 92 |

무결성 검증 PASS — 손상 0, 규격 1024×1024 전부 일치, 인덱스 정합 OK.

**결함 크기 실측**: bbox 변 길이 중앙값이 이미지 변의 **17~48%**. COCO 기준 대형 객체다.
이것이 이후 해상도를 크게 낮출 수 있었던 근거가 됐다.

**환경 변동 실측** (정상 282장):

| 변수 | 실측 | 판정 |
|---|---|---|
| 회전 | 원형 표준편차 **8.0°**, 범위 −20°~+24° | 존재, 셋 중 최대 |
| 위치 | 원판 중심 이탈 중앙 8.8px = 반지름의 2.0% | 소폭 |
| 크기 | 반지름 변동계수 1.84% | 소폭 |
| 조명 | 이미지 간 평균 L 표준편차 1.91/100 (상대 4.5%) | 거의 없음 |
| 색바램 | 색도 표준편차 0.0033 (상대 0.9%) | **사실상 없음** |

→ **MVTec `cable`에는 실제 라인의 환경 변동이 없다.** 강건성을 이 데이터로 직접 검증할 수 없다는 뜻이며, 이후 모든 판단의 전제가 됐다.

## 2. Track C 기준선 (P2·P3)

MobileNetV3-Small, ImageNet 사전학습, FP32, 5-fold.

| 입력 | AUROC | 미검율 | 과검율 | GFLOPs | e2e p50 |
|---|---|---|---|---|---|
| 640 | 0.9994 ± 0.0012 | 0.00 % | 0.87 % | 0.988 | 74.9 ms |
| 384 | 0.9997 ± 0.0006 | 0.00 % | 0.43 % | 0.357 | 54.6 ms |
| 256 | 0.9992 ± 0.0011 | 0.00 % | 1.30 % | 0.160 | 26.9 ms |

5-fold 합산 혼동행렬: **TP 76 / FN 0 / FP 1~3 / TN 230~232**. 8개 불량 클래스 recall 전부 1.000.

**세 해상도를 통계적으로 구분할 수 없다**(차이가 표준편차 이내). "384가 낫다"가 아니라
"640으로 올릴 이유가 없다"가 정확한 표현이다.

### 발견한 문제 — 임계값 τ가 환경 간 이식되지 않는다

| 입력 | 정상 점수 중앙값 범위 | 분리 간격 log10 | τ 범위 |
|---|---|---|---|
| 640 | 2e-11 ~ 2e-4 (**8자릿수**) | 0.25~0.81 | 5.5e-06 ~ 0.68 |
| 384 | — | 0.19~0.90 | 1.2e-08 ~ 0.97 |
| 256 | — | 0.25~0.61 | 1.3e-05 ~ 3.1e-03 |

한 환경에서 정한 절대 확률 임계를 다른 환경에 그대로 쓰면 판정이 무너진다.
조치: `choose_threshold`에 마진 tie-break 추가 + SOP §7.2에 **배포 시 현장 재보정 의무화**.

## 3. Stage 0 — 합성 섭동 강건성 벤치마크

MVTec에 없는 환경 변동을 합성해 저하 곡선을 만들었다. 강도 1배 = 실측값.
28조건 × 5 fold × 3 해상도 = 420 평가.

| 축 | 최대 강도 | AUROC 640/384/256 | 재보정 미검율 % | 과검율 % |
|---|---|---|---|---|
| 무섭동 | — | 0.9994 / 0.9991 / 0.9992 | 0 / 1.3 / 0 | 0.9 / 0.9 / 3.0 |
| 회전 | ±80° | 0.9960 / 0.9930 / 0.9973 | 1.3 / 6.4 / 1.2 | 2.6 / 7.3 / 12.1 |
| 이동 | ±10% | 0.9983 / 0.9919 / 0.9915 | 0 / 1.3 / 5.2 | 3.4 / 1.7 / 9.0 |
| 스케일 | ±20% | 0.9943 / 0.9918 / 0.9983 | 2.7 / 5.3 / 1.3 | 4.7 / 4.7 / 9.5 |
| 밝기 | ±50% | 0.9966 / 0.9844 / 0.9903 | 2.6 / 6.7 / 6.6 | 6.0 / 5.6 / 12.9 |
| **색바램** | 30% | 0.9095 / 0.9353 / **0.8924** | 38.3 / 30.3 / **39.2** | 49.3 / 40.3 / 65.7 |
| **황변** | 30% | 0.9654 / 0.9561 / **0.9018** | 14.6 / 21.3 / **37.4** | 85.5 / 58.8 / 81.5 |
| **정반사** | 면적10% | 0.8852 / 0.8314 / **0.8273** | 43.2 / 49.7 / **56.3** | 94.9 / 99.6 / **100.0** |

**판정 4가지**

1. **기하 축 전부 강건.** 회전을 실측의 10배인 ±80°까지 밀어도 AUROC 0.993~0.997.
2. **색 축 붕괴.** 재보정으로도 미검율 30~39% — 임계값 문제가 아니라 표현 자체가 무너짐.
3. **정반사가 최대 취약점.** 면적 **1%만** 가해도 AUROC 0.964로 떨어지고, 10%면 과검 **100%**
   (전 샘플 NG 판정 = 판정기 기능 정지).
4. **해상도가 강건성을 바꾼다.** 무섭동 정확도는 세 해상도가 같은데 섭동 하에서는 640이 일관되게
   우수(황변 0.9654 vs 256의 0.9018). → 정확도만 보고 내린 "256 채택" 권고를 **보류**했다.

> 미검율(고정 τ)이 낮은 건 착시다. 과검율 100% 구간에서 미검 0%는 "전부 NG 판정"이다.
> 미검율 단독 보고는 무의미하며 과검율·AUROC와 함께 봐야 한다.

## 4. 제안 문서 3건 분석

### `code_artifact.md` — 부분 채택
- 결함 이중성(구조 vs 논리) 포착은 정확. `cable_swap` 마스크가 케이블 단면 **전체**를 덮는 것을 P1에서 독립 확인
- 상대 색상 순서 아이디어는 Stage 0에서 **입증** (색바램 축 붕괴)
- ECC/Affine 정렬·고정 마스크는 **기각** (기하 축 이미 강건)
- CLAHE는 우선순위 낮음 (조명 변동 4.5%뿐)

### `sota.md` — 보류
- "케이블의 비정형 유동성(Non-rigid bend)"이라는 핵심 전제가 **사실과 다르다** — 본 데이터는 절단면 촬영
- Deformable Registration / Slot Attention / GNN 전부 데이터에 없는 문제를 겨냥
- DoD 충돌: DINOv2 ViT-S/14 단독으로 INT8 약 21.6 MB(상한 10 MB 초과), 연산량 약 100배
- Stage 0 실측으로 **전 구성요소가 근거를 잃었다**

### `detection_참조.md` — 1건만 가치, 그 1건은 큼
- 10건 중 7건이 "결함을 더 잘 찾는 방법" → 우리는 이미 미검율 0%
- #3·#4(소형객체 YOLO): 우리 결함은 최소 17%로 대형 → **적용 근거 없음**
- #5·#9(하네스 경로/3D): 절단면 촬영이라 휘어짐 자유도 없음 → **적용 불가**
- #6 LogiCo: 서지 오류 발견(2024 arXiv → **ECCV 2026**). Track B 진행 시 후보
- **#1 CableInspect-AD: 최우선 채택 권고** — 실측 현장 데이터, 불량 2,639장(현재의 **29배**),
  논문이 *"임계값 설정을 위한 표본 수집의 어려움"* 을 직접 다룸.
  우리의 구조적 한계 3개(대리 데이터·표본 부족·τ 이식성)를 한 번에 해소
- 10건 중 **6건에 저자 표기 없음** — 인용 전 전수 검증 필요

> 세 문서 모두 같은 패턴 — **데이터를 보기 전에 방법부터 골랐다.** 실측하니 정확도는 포화였고
> 진짜 문제는 다른 곳(강건성·임계값)에 있었다.

## 5. Stage 1 — 값싼 처방 (완료, C 채택)

Stage 0 결과에 따라 **기하 정렬은 제외**하고 색·반사 대응에 집중했다.

| 변형 | 구성 | 학습 | 무섭동 AUROC | 미검율 | 과검율 | e2e p50 | 학습시간 |
|---|---|---|---|---|---|---|---|
| 기준선 | prep 없음 / aug=medium | 완료 | 0.9992 ± 0.0011 | 0.00 % | 1.30 % | 26.9 ms | 49분 |
| **A** | prep 없음 / **aug=robust** | **완료** | 0.9971 ± 0.0045 | 1.33 % | 1.30 % | 24.9 ms | 41분 |
| **B** | **prep=gray+spec** / aug=medium | **완료** | 0.9988 ± 0.0017 | 0.00 % | 0.87 % | 48.8 ms | 68분 |
| **C (채택)** | prep + aug=robust | 완료 | 0.9980 ± 0.0041 | 1.33 % | 0.87 % | **18.75 ms** | 96분 |

> 기준선·A·B 행의 e2e 수치는 학습 중 측정돼 경합 영향이 있다. **무경합 실측은 아래 별도 표** 참조.

**관찰**
- 네 변형 모두 무섭동 AUROC ≥ 0.997 유지 — 사전 등록 기준 4번(≥0.99) 통과. 판정은 섭동 축에서 갈렸다
- 강건 증강의 대가는 무섭동 AUROC 0.9992 → 0.9971(A) / 0.9980(C)로 작다
- 전처리는 학습·추론 양쪽에 비용을 더한다 — 학습 68분 vs 41분(1.66배), 추론 +6.2 ms

### Stage 1 구현 중 잡은 문제 3건

| 문제 | 조치 |
|---|---|
| 회전 추정기가 위상 백색화 때문에 고장 | 평탄 상호상관으로 교체 — 복원 오차 16.2° → **2.9°±3.5°** |
| 색도 정규화가 색바램을 못 고침 (출력 색도 = 입력 색도, 수학적 항등) | 그레이월드 정규화 추가 — 채널 캐스트 15.5% → **4.1%** |
| 정반사 억제가 정상 구리반사를 파괴 (무섭동 25.75dB 훼손, 140.7ms) | 국소분산 판별자로 3차 재설계 — 복원 **+2.2dB**, 무섭동 훼손 **86.0dB**(무손상), 수정 화소 0.28% |

정반사 판별의 핵심: 포화 화소 6.28%는 대부분 **구리 소선의 고유 반사**다. 임계·면적으로는 못 가른다.
유효한 판별자는 **국소 표준편차** — 외란 하이라이트 내부 0.36 vs 구리 반사 6.12, **17배 차이**.

### 판정 결과 — 사전 등록 기준으로는 전원 불합격, C를 채택

| 변형 | 색바램 30% | 황변 30% | 정반사 10% |
|---|---|---|---|
| 기준선 | 0.8924 / 39.2% / 65.7% | 0.9018 / 37.4% / 81.5% | 0.8273 / 56.3% / 100.0% |
| A | 0.9835 / 10.6% / 13.8% | 0.9750 / 9.2% / 18.9% | 0.9210 / 26.2% / 57.9% |
| B | **0.9974 / 2.7% / 5.2%** | **0.9986 / 0.0% / 3.0%** | 0.8382 / 57.7% / 100.0% |
| **C** | **0.9974 / 1.3% / 2.2%** | **0.9977 / 1.3% / 2.6%** | 0.9228 / 35.6% / 57.1% |

(AUROC / 재보정 미검율 / 고정 τ 과검율. 합격선 = 0.95 / 5% / 50%)

**세 변형 모두 정반사 축에서 탈락했다.** 규칙대로면 "값싼 처방 불충분 → Stage 2"다.
기준을 사후 완화하는 대신 **결정을 분리**해 C를 채택했다 — 근거는 SOP §8.3.

1. **색 축 완전 해결** — 미검율 39.2% → 1.3%, 37.4% → 1.3%. 그레이월드가 채널 게인의 역연산이라는 예측이 실측으로 확인
2. **정반사는 증강 > 전처리** (A 0.9210 vs B 0.8382). 전처리가 PSNR을 +2.2 dB 복원했는데도 모델 성능은 안 올랐다 — **픽셀 복원과 표현 보존은 다른 문제**
3. **상보적** — C가 색 축 최고이면서 정반사도 A와 동급. 나빠지는 축 없음
4. **비용 작음** — 전처리 6.2 ms 고정, 무섭동 AUROC 손실 0.0012
5. **B 기각** — 정반사 미개선 + 색 축도 C보다 못함

**정반사는 독립 과제로 승격**(SOP §13 리스크 등재). 착수 전 확인할 것: 실제 라인의 정반사 발생 빈도
— **조명 설계·편광 필터로 물리적 저감이 모델보다 저렴하다**.

### 무경합 지연 실측 (단일 스레드, DoD 기준 조건)

| 설정 | 전처리 | 모델 | e2e p50 | p95 |
|---|---|---|---|---|
| 256 / 없음 | 0 | 7.65 | 12.59 | 15.96 |
| **256 / gray+spec (확정)** | 6.16 | 7.48 | **18.75** | 21.68 |
| 384 / gray+spec | 6.20 | 12.72 | 27.07 | 32.25 |
| 640 / gray+spec | 6.39 | 33.19 | 52.16 | 64.50 |

전 설정이 DoD 100 ms 대비 5~8배 여유. 이전 측정치는 CPU 경합으로 약 2배 부풀려져 있었다.
**멀티스레드가 오히려 느리다**(256px 12.59 vs 10-스레드 17.17 ms) — 모델이 작아 동기화 오버헤드가
병렬 이득을 넘는다. 엣지 배포는 단일 스레드가 유리하다.

### 판정 기준은 결과 보기 전에 사전 등록했다

`reports/stage1_decision_criteria.md` — 붕괴 3축(색바램30%/황변30%/정반사10%)에서
**AUROC ≥ 0.95 + 재보정 미검율 ≤ 5% + 과검율 < 50%** 를 전부 충족해야 "회복" 인정.
A 합격 시 전처리 불필요로 결론하며, B·C가 최악축을 +0.02 이상 개선하지 못하면 전처리 비용을 정당화하지 않는다.

## 6. 현재 실행 중

```
Stage 1-C 학습 (fold1/5)                      ~50분
  ↓
score_folds ×3 → robustness_bench ×3          ~25분
  ↓
report_stage1 + report_track_c
  ↓
bench_latency (무경합, 1스레드 + 전스레드)      ~10분
```

시스템 메모리가 빠듯해(여유 3.7/15.7 GB) 완료 감시 프로세스가 한 번 정리됐다.
작업 체인 자체는 무사하다.

## 8. 누적 한계 — 결과 해석 시 반드시 함께 읽을 것

1. 모든 수치가 **val fold 기준**이고 τ도 같은 val에서 정해 **낙관적으로 편향**돼 있다.
   편향 없는 값은 홀드아웃에서만 얻는다 — **홀드아웃은 아직 한 번도 쓰지 않았다**(P5 전용)
2. fold당 val 불량 15~16장. 미검 0건이어도 rule of three 기준 95% 상한이 fold 단위 약 20%,
   5-fold 합산(76장)해도 약 3.9%다. fold 간 학습셋이 겹쳐 이 값도 낙관적이다
3. 클래스별 recall 1.000은 클래스당 n=8~12에서 나온 값이다
4. **합성 섭동은 실제 라인 변동의 대리다.** 섭동 모형이 현장과 다르면 결론도 달라진다
5. robust 증강을 쓴 변형(A·C)은 시험 섭동과 **같은 축**을 학습에서 겪었다(범위는 더 좁게).
   그 개선은 분포 내 강건성이며 미지 변동 일반화가 아니다
6. 지연시간·메모리는 **개발 머신 CPU** 값이다. 타깃 하드웨어에서 §9.3(열 스로틀링 포함)으로
   재측정해야 배포 판단이 된다
7. Track A(YOLO)·Track B(비지도) 미수행 — §1.2 연구질문 1(어느 태스크가 유리한가)은
   Track C 단독으로 답할 수 없다
8. MVTec AD는 **CC BY-NC-SA 4.0(비상업)** 이다. 상업 제품 적용은 별도 확인 필요
