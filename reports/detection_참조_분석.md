## 0. 결론 — 참조 목록의 조준점과 실제 병목이 어긋난다

10건 중 **7건이 "결함을 더 잘 찾는 방법"**(YOLO 소형객체 최적화, 어텐션, 논리결함 검출)을 다룬다.
그런데 본 연구의 현 상태는:

| 지표 | 현재 (Track C, 256px) |
|---|---|
| 미검율 | **0.00 %** (불량 76장 중 0건) |
| AUROC | 0.9992 ± 0.0011 |
| 클래스별 recall | 8종 **전부 1.000** |
| 연산량 | 0.16 GFLOPs, e2e p50 27 ms |

**정확도에 개선 여지가 없다.** 실제 병목은 Stage 0에서 드러난 두 가지다:

1. **환경 변동 강건성** — 색바램 30%에서 AUROC 0.89, 정반사 면적 10%에서 과검율 100%(판정기 기능 정지)
2. **임계값 이식성** — τ가 fold마다 8자릿수 차이(1.3e-5 ~ 0.68). 현장 이식 불가

10건 중 이 두 문제를 정면으로 다루는 것은 **1건(#1 CableInspect-AD)뿐**이다. 나머지 9건은 이미 해결된 문제를 겨냥한다.

**가장 가치 있는 항목은 #1이며, 방법론이 아니라 데이터셋으로서 가치가 있다.**

## 1. 개별 평가

### 최우선 — 즉시 추진 권고

#### #1 CableInspect-AD (NeurIPS 2024 D&B) — **채택 권고**

서지 확인 완료. Hydro-Québec + Mila, 공개 데이터셋.

| 항목 | 내용 |
|---|---|
| 규모 | 고해상도 4,798장, 전문가 주석 6,023건 |
| 구성 | 정상 2,159 / 이상 2,639, 케이블 3종(색·질감·꼬임 상이) |
| 주석 | 이미지 레벨 + bbox + 픽셀 마스크 |
| 결함 | Hydro-Québec이 꼽은 실제 최빈 7종, 심각도 등급 포함 |
| 환경 | **로봇 전력선 검사** — 통제 실험실이 아닌 실제 현장 |

**왜 최우선인가 — 본 연구의 두 구조적 결함을 동시에 메운다.**

1. **검증 데이터 부족 해소.** `reports/연구후보_분석.md`에서 지적했듯 MVTec `cable`은 조명 변동 4.5%, 색바램 0.9%로 환경 변동이 사실상 없다. 그래서 강건성을 합성 섭동으로 **대리 측정**할 수밖에 없었고, "섭동 모형이 현장과 다르면 결론도 달라진다"는 한계를 계속 달고 다녔다. CableInspect-AD는 실제 현장 변동을 포함한 실측 데이터다.
2. **임계값 문제를 정면으로 다룬다.** 이 논문의 Enhanced-PatchCore는 *"검출 임계값 설정을 위한 다양한 정상·이상 표본 수집의 어려움"* 을 해결 대상으로 명시한다. 이것이 정확히 우리가 발견한 τ 이식성 문제다(§7.2 정책 보완 사항).

또한 불량 표본이 2,639장으로 MVTec `cable`의 92장 대비 **29배**다. 현재 "fold당 불량 15~16장, rule of three 상한 20%"라는 통계적 한계가 근본적으로 완화된다.

**실행**: 라이선스·접근 조건 확인 → 확보 → 현 Track C를 그대로 평가(전이 성능) → Stage 0 합성 섭동 결과와 실측 변동 결과 대조. 대조가 맞으면 우리 섭동 모형이 타당함을 입증하는 것이고, 어긋나면 섭동 모형을 실측에 맞춰 교정한다.

### 조건부 — 실제 제품 특성에 따라 달라짐

#### #3 CIA-YOLO (YOLOv11 + CBAM + Inner-IoU), #4 TW-YOLO (Triplet Attention + WIoU)

둘 다 **소형 객체(Small Object) 검출 최적화**다. 강철 케이블 표면의 미세 단선·마모가 대상.

**현 데이터에는 적용 근거가 없다.** 실측(`reports/SUMMARY_cable_trackC.md` §1.2):

| 클래스 | bbox 폭 중앙값 | 높이 중앙값 |
|---|---|---|
| combined | 45.3 % | 48.0 % |
| missing_cable | 32.7 % | 32.0 % |
| **missing_wire (최소)** | **16.8 %** | **17.1 %** |

가장 작은 클래스도 이미지 변의 **17%**로 COCO 기준 대형 객체다. CBAM·Inner-IoU·WIoU는 전부 소형 타겟의 IoU 안정성과 특징 보존을 겨냥한 장치라 여기서는 이득이 없다. 실제로 입력을 256px로 낮춰도 전 클래스 recall 1.000이 유지됐다(A1 ablation).

**보류 조건**: 실제 제품의 결함이 이미지 변의 5% 이하로 작다면 그때 재검토한다. 그 경우 §8.2 A1(해상도) 결론도 함께 뒤집힌다 — 우리는 "해상도를 낮춰도 된다"고 결론냈지만, 그건 결함이 크기 때문이었다.

> 서지 주의: #4의 게재처로 적힌 "Hill Publishing Group"은 심사 품질이 확인되지 않은 출판사다. 인용 전 검증 필요.

#### #6 LogiCo (ECCV 2026), #7 Logical AD with Masked Image Modeling — **Track B 진행 시에만**

LogiCo 서지 확인 완료: arXiv 2606.28688, **ECCV 2026**, 구현 공개(github.com/cnulab/LogiCo). 부품 단위 특징 재구성 + 분할맵 판별자로 개수 관련 논리 결함까지 처리하며, MVTec-LOCO·MVTec-AD·VisA·Real-IAD 4개 벤치마크 SOTA.

> 참조 문서는 "arXiv preprint, 2024"로 적었는데 연도·게재처가 다르다.

**우리 데이터와의 관계**: 논리 결함(`cable_swap`, `missing_cable`, `missing_wire`)은 실재하고, P1 라벨 검증에서 `cable_swap` 마스크가 케이블 단면 **전체**를 덮는 것도 확인했다(국소 텍스처 이상 아님). SOP §3.2에서 "패치 단위 이상탐지(PatchCore/PaDiM)가 구조적으로 불리할 것"이라 가설을 세웠는데, LogiCo·MIM은 정확히 그 약점을 노린 방법이다.

**그러나 현재는 채택 근거가 없다** — Track C가 이 3개 클래스를 recall 1.000으로 이미 잡는다. 값어치가 생기는 경우는 둘뿐:
- Track B(비지도, 정상만으로 학습)를 본선으로 갈 때 — 불량 데이터 없이 논리 결함을 잡아야 하므로
- 불량 **위치**를 출력해야 할 때 (§2.1 판정 출력 형태 미확정)

GPU 확보 후 Track B를 수행한다면 EfficientAD와 함께 LogiCo를 비교 후보에 넣을 만하다. 단 연산량은 별도 확인이 필요하다 — 본 프로젝트 DoD는 INT8 10MB / 단일스레드 100ms다.

#### #8 Edge-oriented cable surface inspection (SPIE 2025) — **§9.3 참고자료로 활용**

OpenCV 전처리 + 경량 검출기를 Raspberry Pi에서 실시간화한 파이프라인. **목표 정합성이 10건 중 가장 높다**(SOP §1.1과 동일한 문제 설정).

다만 우리는 이미 그 방향으로 와 있다 — MobileNetV3-Small 0.16 GFLOPs, 개발 CPU e2e 27ms. 얻을 것은 방법이 아니라 **배포 실무 지식**이다: 타깃 하드웨어 선정 근거, 카메라-처리 파이프라인 구성, 실시간 처리량 확보 방식. §2.1에서 미확정인 "타깃 하드웨어"를 정할 때 참고한다.

> 서지 주의: 저자 표기가 없다. SPIE Proceedings는 학회 발표집이라 심사 강도가 저널과 다르다.

### 적용 불가 — 문제 설정이 다름

#### #5 Wiring harness length (YOLO + 스켈레톤화), #9 3D Point Cloud + B-Spline

둘 다 **길게 뻗어 휘어진 케이블**의 3차원 궤적·길이를 다룬다.

**본 데이터는 케이블을 절단한 단면 촬영이다.** 휘어짐이라는 자유도가 존재하지 않는다. `sota.md`의 Deformable Registration을 기각한 것과 **같은 이유**로 기각된다. #9는 추가로 3D 센서가 필요해 현 2D 단일 카메라 설정과 맞지 않는다.

**보류 조건**: 실제 제품이 와이어 하네스처럼 배선 경로 자체를 검사해야 하는 형태라면 문제 설정이 통째로 바뀐다. 그 경우 본 SOP의 태스크 정의(§1.2)부터 다시 써야 한다.

#### #2 PatchCore — 이미 SOP에 반영됨

SOP §6 Track B 후보 표에 이미 있다("정확도 높음 / 엣지 적합성 낮음 — 메모리 뱅크 부담"). 새로운 정보는 없다. 정상 224장 × 324패치 × 384차원 × 4B ≈ 111 MB(코어셋 1% 축약 시 약 1.1 MB)라는 추정도 이미 §3.3에 기록해 뒀다.

#### #10 Wiring harness fault detection system

시스템 아키텍처·산업 도입 사례. 모델 기여는 없고 **배포 계획(§9) 참고자료** 수준이다. 저자·게재처 표기가 없어 검증이 필요하다.

## 3. 참조 목록이 빠뜨린 영역 — 실제 병목에 맞는 문헌

본 연구의 병목은 정확도가 아니라 **환경 변동 강건성**과 **임계값 이식성**이다. 이 영역의 문헌이 목록에 없어 보완 조사했다.

| 문헌 | 관련성 |
|---|---|
| **Robust AD: A Real World Benchmark Dataset for Robustness in Industrial Anomaly Detection** | 우리가 합성 섭동으로 만든 강건성 벤치마크의 **실물판**. Stage 0 설계의 타당성 검증에 직접 쓸 수 있다 |
| **PIAD: Pose and Illumination agnostic Anomaly Detection** (CVPR 2025) | 자세·조명 불변 이상탐지. 우리 Stage 0에서 무너진 축 중 조명 계열을 정면으로 다룬다 |
| **Visual Anomaly Detection under Complex View-Illumination Interplay** (arXiv 2505.10996) | 시점-조명 상호작용 대규모 벤치마크 |
| **Industrial anomaly detection with domain shift: A real-world dataset and masked multi-scale reconstruction** (Computers in Industry, 2023) | 도메인 시프트 실데이터 + 방법. MVTec→실라인 전이 문제와 직결 |
| **Unsupervised industrial AD using paired well-lit and low-light images** (JCDE 2025) | 조명 쌍 데이터로 조명 불변성 학습 |
| **awesome-industrial-anomaly-detection** (GitHub, M-3LAB) | 산업 이상탐지 논문·데이터셋 지속 갱신 목록 — 후속 조사 출발점 |

> 검색 결과 기반이며 원문을 직접 읽지는 않았다. 채택 전 검증 필요하다.

**핵심**: 참조 문서가 "무엇을 더 잘 찾을까"를 물었다면, 지금 물어야 할 것은 **"현장에서 무너지지 않으려면 무엇이 필요한가"**다. 위 문헌들이 그 질문에 답한다.

### 재확인된 결론

이 참조 목록은 `sota.md`와 **같은 패턴의 오류**를 반복한다 — 데이터를 보기 전에 방법부터 고른 것이다. 실측을 먼저 하니 정확도는 이미 포화였고(미검율 0%), 진짜 문제는 다른 곳(강건성·임계값)에 있었다. 10건 중 9건이 전자를 겨냥한다.

다만 `detection_참조.md`는 앞선 두 문서보다 **실무적으로 더 나은 기여**를 한다 — #1 CableInspect-AD는 본 연구가 겪고 있는 구조적 한계(대리 데이터, 표본 부족, 임계값 설정)를 한 번에 해소할 수 있는 실제 자원이다. 이 한 건만으로도 문서의 값어치가 있다.
